## 1. 資安

- [x] 🔴 **一個格式錯誤的 socket 訊息就能讓整台伺服器當掉**（2026-10-25 已修）
  - 原本：送 `createRoom`，`name` 給數字 → `name.trim is not a function` → process 結束，所有人斷線。
  - 修法：`server.js` 開頭用 `io.use` 把每個 socket handler 包上 try/catch，出錯只記 log；`createRoom` / `joinRoom` / Top Ten 回答與自訂題目另外做型別檢查；socket 訊息上限 64KB。
- [x] 🔴 **玩家名字有 XSS 漏洞**（2026-10-25 已修）
  - Top Ten 結算畫面的名字和回答改用 `escapeHTML`；骷髏牌整個刪掉了。
  - 全站掃過所有 `innerHTML` 模板，其餘插入的都是伺服器算的數字或固定文字。
- [x] 🔴 **名字沒有長度限制**（2026-10-25 已修）：伺服器端 `cleanName()` 只收字串、去掉 `<` `>` 和控制字元、最多 10 字（和輸入框一致）；未知的 `gameType` 一律當成驚爆倫敦。
- [ ] 🟠 **房號容易被猜到**：只有 4 個英文字母（約 45 萬種組合），也沒有限制猜錯次數。陌生人可以用程式亂猜，闖進別人的房間。
  - 做法：加入失敗次數限制（每個 IP / 每個連線），或把房號加長到 5–6 碼，或讓房主可以鎖房。
- [ ] 🟡 檢查 socket 訊息大小上限（`maxHttpBufferSize`）和各事件的頻率限制（目前只有聊天有）。

## 2. 房間與資源

- [ ] 🟠 **沒有房間總數上限**：有人用程式狂開房間（每間還加滿 AI），記憶體就會被吃光。
  - 做法：限制全站房間數和每個 IP 能開的房間數，超過就拒絕開房。
- [ ] 🟠 **掛著不玩的房間不會被清掉**：人還連著但不玩了（手機螢幕開著放在桌上），房間會一直留著。
  - 做法：房間若 N 分鐘沒有任何操作就關閉，並通知房內玩家。
- [ ] 🟡 確認所有計時器（`setTimeout` / `setInterval`）在房間刪除時都有清掉（`deleteRoom` 有清一部分，各遊戲自己的計時器要再檢查）。

## 3. 部署與穩定性

- [ ] 🟠 **每次部署都會把所有人踢出去**：房間只存在記憶體裡，Render 每次重新部署，所有正在玩的局都會消失。
  - 現在的流程是「合併 agent PR → 自動部署」，所以每合併一次，全站都會斷線。
  - 做法（擇一）：只在固定的冷門時段合併 / 部署；或關掉自動部署改手動；或把房間狀態存到外部（例如 Redis）讓重啟後能恢復（工程量大）。
- [ ] 🟠 **Render 免費方案會休眠**：閒置約 15 分鐘就休眠，下一個人要等快一分鐘才醒。從社群連進來的人可能等不及就關掉了。
  - 做法：改用付費方案，或用 uptime 監控定時 ping 讓它不休眠。
- [ ] 🟠 **沒有監控**：網站掛掉時沒有任何通知。
  - 做法：加一個免費的 uptime 監控（例如 UptimeRobot），掛掉時寄信給你。
- [ ] 🟡 **流量上限**：目前是單一 Node process、房間存在記憶體裡，不能直接開第二台分擔流量。
  - 單台應該撐得住幾百個房間，初期不是瓶頸。
  - 真的要擴充時，需要 Redis adapter 加 sticky session，改動很大。

## 4. 內容與管理

- [ ] 🟠 **回報按鈕會變成垃圾訊息的入口**：issue 公開在 GitHub 上，陌生人可能送廣告、罵人的話，或寫上自己的個資。
  - 現在是每個 IP 每 10 分鐘 5 則、全站每小時 40 則（`report.js`）。
  - 做法：調低上限；或先存在伺服器端等你審核，通過後才開 issue；或在回報表單提醒「內容會公開，不要寫個資」。
  - 目前 agent 只處理你按讚的 issue，所以垃圾回報不會讓 Claude 自動去改程式。
- [ ] 🟠 **名字和聊天室的內容管理**：一定會有人取難聽的名字，或在聊天室洗版、罵人。
  - 做法：房主可以踢人；簡單的髒話過濾；檢舉功能。
- [ ] 🟡 issue 內文目前會附上玩家裝置資訊（User-Agent），公開時要考慮要不要拿掉。

## 5. 版權與商標

- [ ] 🟠 **遊戲名稱、美術和規則文字的版權**：時限炸彈、截碼戰、化裝舞會、阿瓦隆、一夜終極狼人、Top Ten 都是有出版商的商業桌遊。
  - 朋友之間玩沒人會管；公開而且收錢的話，可能會收到下架通知。
  - 遊戲機制本身通常不受保護，名稱、美術和文字才是主要風險。
  - 做法：改用自己取的名字、自己的美術和自己寫的說明。
  - ⚠️ 建議問一下懂智慧財產權的人，這裡不是法律意見。
